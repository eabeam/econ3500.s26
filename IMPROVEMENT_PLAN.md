# ECON3500 Site Improvement Plan

This document outlines five priority improvements to enhance usability, stability, and organization of the course website.

---

## 1. Update Hugo Version and Fix Broken Links

**Problem:** The site uses Hugo 0.92.2 (January 2022) via Netlify, which is significantly outdated. Additionally, the GitHub edit URL contains a typo (`ec3500` instead of `econ3500`), causing 404 errors.

**Actions:**
- [ ] Update `netlify.toml` to use Hugo 0.120+ (change `HUGO_VERSION = "0.92.2"` to current stable)
- [ ] Fix `params.yaml` line 72: change `ec3500.s26` to `econ3500.s26` in the edit URL
- [ ] Test build locally with updated Hugo version before deploying

**Impact:** Eliminates security vulnerabilities, ensures compatibility with modern features, and restores the "Edit this page" functionality.

---

## 2. Clean Repository of Build Artifacts and System Files

**Problem:** The repository contains 74 LaTeX build artifacts (.aux, .log, .synctex.gz), 32 .DS_Store files, iCloud placeholder files, and a corrupted file (`01-lab2.texfdsafaewf`).

**Actions:**
- [ ] Add to `.gitignore`:
  ```
  *.aux
  *.log
  *.synctex.gz
  *.out
  .DS_Store
  *.icloud
  ```
- [ ] Remove tracked artifacts: `git rm --cached` for the above patterns
- [ ] Delete corrupted file: `content/assignment/01-lab2.texfdsafaewf`
- [ ] Delete iCloud placeholders in `static/content/`

**Impact:** Reduces repository size, prevents merge conflicts, and removes confusion from stray files.

## 3. Consolidate Schedule Data and Remove Stale Configuration

**Problem:** Two schedule sources exist: `/data/schedule.yaml` (old, summer dates) and `/content/schedule/_index.md` (current, Spring 2026). Disabled config files and orphaned reports clutter the root directory.

**Actions:**
- [ ] Delete or archive `/data/schedule.yaml` (currently unused)
- [ ] Move disabled configs to `config/_archive/`:
  - `_config.toml.disabled.toml`
  - `config.yaml.disabled.yaml`
- [ ] Delete generated reports from root:
  - `linkcheck-*.md`
  - `external-links.txt`
- [ ] Move maintenance scripts to `/scripts/`:
  - `external_check.sh`
  - `update_academic.sh`

**Impact:** Single source of truth for schedule, cleaner project root, easier navigation for contributors.

---

## 4. Enhance Homepage for Better Student Orientation

**Problem:** The homepage is minimal with only a hero banner. Students landing on the site have no immediate guidance on where to start or what the course covers.

**Actions:**
- [ ] Add a welcome section to `/content/home/` with:
  - Brief course description (what students will learn)
  - Quick links: "Start Here" pointing to syllabus, current week's content
  - Upcoming deadlines or announcements widget
- [ ] Consider adding the `courseinfo` shortcode output to the homepage
- [ ] Add a "Getting Started" callout for new students

**Impact:** Improved first-visit experience, reduced confusion about navigation, clearer student pathway through course materials.

---

## 5. Convert Rmd Files to Plain Markdown and Eliminate R Dependency

**Problem:** The site uses 39 `.Rmd` files, but none contain actual R computations. They only use R syntax to call Hugo shortcodes (e.g., `` `r blogdown::shortcode("slides")` ``). This creates an unnecessary dependency on R, blogdown, and knitr for building the site.

**Current state:**
- 39 Rmd files in `/content/` (labs, problem sets, content pages, resources)
- R syntax used only for shortcode calls, not data analysis
- Stata code blocks are static (no execution needed)
- Local preview requires blogdown, but `hugo server` would suffice

**Actions:**
- [ ] Convert all `.Rmd` files to `.md`:
  - Rename files from `.Rmd` to `.md`
  - Remove `output: blogdown::html_page` from YAML front matter
  - Replace `` `r blogdown::shortcode("slides")` `` with `{{</* slides */>}}`
  - Replace `` `r blogdown::shortcode('tweet', 'url')` `` with `{{</* tweet "url" */>}}`
  - Replace `` `r htmltools::HTML("{{< youtube ID >}}")` `` with `{{</* youtube ID */>}}`
- [ ] Keep `syllabus-pdf.Rmd` only if PDF generation via LaTeX is still needed
- [ ] Update local development workflow:
  - Use `hugo server` or `./view.sh` instead of `blogdown::serve_site()`
  - Remove blogdown dependency from workflow
- [ ] Delete corresponding `.html` files generated by knitr (Hugo will regenerate)

**Files to convert (39 total):**
| Directory | Count | Examples |
|-----------|-------|----------|
| `/content/assignment/` | 16 | 01-ps.Rmd, 03-lab.Rmd, RP-*.Rmd |
| `/content/content/` | 13 | 01-content.Rmd through 13-exam3.Rmd |
| `/content/bonus/` | 7 | stata-problems.Rmd, rp-resources.Rmd |
| `/content/` (root) | 2 | 404.Rmd, index files |
| `/content/syllabus/` | 1 | syllabus-pdf.Rmd (keep if needed) |

**Impact:**
- Eliminates R/blogdown/knitr dependency for site builds
- Faster local preview with plain `hugo server`
- Simpler contributor workflow (just Hugo, no R knowledge needed)
- Netlify builds become more reliable (fewer dependencies)
- Stata code blocks display identically (just syntax highlighting, no execution)
